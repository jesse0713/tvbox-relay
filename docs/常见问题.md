# 常见问题

## 电视提示「配置加载失败 / 界面一片空白」

按这个顺序查，多数在第一步就能定位：

1. **中转在跑吗？** 在电脑浏览器打开 <http://127.0.0.1:8080/health>，不是 `ok` 就双击 `relay\启动中转.cmd`，再看不到结果就看 `relay\relay.log` 最后几行。
2. **电视能到这台电脑吗？** 手机连同一 WiFi，浏览器打开 `http://<电脑IP>:8080/health`。手机能开、电视不能 → 电视与电脑不在同一网段（访客网络、5G/2.4G 隔离、AP 隔离都会这样）。
3. **防火墙放行了吗？** 双击 `relay\放行防火墙.cmd`，UAC 点「是」。
4. **地址填对了吗？** 必须是 `http://<电脑IP>:8080/tv.json`，不要 `https`、不要在末尾少写路径。

```powershell
netstat -ano | findstr :8080     # 没有 LISTENING 就是服务没起
Get-NetFirewallRule -DisplayName "TVBox Relay*"   # 没有输出就是没放行
```

## 手机能打开状态页，电视打不开

同 WiFi 但不同网段最常见。检查电脑 IP 与电视 IP 前三位是否一致：

```powershell
ipconfig | findstr IPv4
```

不一致（比如电脑 `192.168.1.x`、电视 `192.168.2.x`）说明中间有二级路由或访客网络，把电视接到主路由的 WiFi 即可。

## 每天第一次打开很慢，之后正常

正常现象。配置缓存 120 秒、静态资源缓存 24 小时，第一次要从中转机去上游取 `spider.jar` 等文件。上游是 GitHub 镜像时，几百 KB 的 jar 可能要几秒。

## 报告里显示某条源「异常」，但电视照样能看

说明中转已经自动切到备源了，不需要处理。想看切到哪条：

```powershell
Select-String "failover" relay\relay.log | Select-Object -Last 5
```

## 改了策略，点播还是「播几秒缓冲几秒」

先确认点播真的走了加速，而不是直连上游：

```bash
curl -s http://127.0.0.1:8080/vod/stats
```

- `conns` 应为 28 左右，`done/total` 在涨 → 加速生效，卡顿来自上游本身或电视解码；
- `total` 为 0 或没有输出 → 点播没走 `/vod/*`，通常是 `sources.json` 里的站点没被改写（代码里的 `wrap_vod_sites` 只改写 `api` 是 http 且非 js/json 的站点）。

再提高并发试试（先确认宽带上行没打满）：

```powershell
set TVBOX_VOD_CONNS=40
python relay\tvbox-relay.py
```

也可以用 `tools\vod-test.py` 模拟播放器拉一整集，看每段耗时：

```bash
python tools/vod-test.py 量子 --segs 30
```

## 直播只有部分频道黑屏 / 有声音没画面

单条线路的问题，不是中转的问题。中转已经把测速不达标的线路过滤掉了，剩下的仍可能在晚高峰失效。换一条：

```bash
python tools/probe-live.py --name 湖南卫视   # 看这条线路的码率和实测速度
```

若只有声音没画面，多半是 HEVC（H.265）编码而电视只支持 H.264，用 `tools\diagnostics\codec-check.py` 确认：

```bash
python tools/diagnostics/codec-check.py
```

## 启动时报「端口已被占用」

进程被杀掉了但没释放，或者别的程序占着 8080：

```powershell
$p = (Get-NetTCPConnection -LocalPort 8080 -State Listen).OwningProcess
Get-Process -Id $p | Select-Object Id,ProcessName,Path
Stop-Process -Id $p -Force
```

确认不是自己要的程序后，也可以换端口：`set TVBOX_RELAY_PORT=8081`，然后电视地址同步改成 `:8081`。

## 改了 sources.json，电视没变化

- 中转按 mtime 重读，保存后几秒内生效；但 `/tv.json` 本身有 120 秒缓存，电视端也可能缓存配置——在 TVBox 里点一次「重新加载」或退出重进。
- 确认改的是 `active` 字段的值（要和 `items[].id` 完全一致），不是 `role` 或 `name`。
- 看日志确认实际用的是哪条：

```powershell
Select-String "video failover|asset" relay\relay.log | Select-Object -Last 3
```

## 电脑一睡眠，电视就打不开

这是本方案唯一的硬限制：中转跑在这台电脑上，电脑睡了服务就没了。

- 电源选项里把「睡眠」设为「从不」，或只在看电视时唤醒；
- 更彻底的做法是把它挪到 NAS / 软路由（见[部署指南](部署指南.md)第 9 节），功耗和稳定性都更好。

## 磁盘被缓存吃满

分片缓存在 `relay\vodcache\s\`，默认上限 4 GB，超过就从最旧的删到 80%。想更省：

```powershell
set TVBOX_VOD_CACHE_MB=1024
```

停服务后可以直接清空整个目录，不影响配置。

## 计划任务没跑 / 上次运行结果不是 0

- 退出码 `1` 表示有源不可用（脚本故意这么返回），看 `report.txt` 里的「异常」行；
- 任务没触发：检查「条件」里是不是勾了「仅在使用交流电源时」和「空闲时才运行」——笔记本上这两个开关会让任务静默跳过；
- 手动跑一次看报错：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\daily-check.ps1
```

## `live6.m3u` 不生成 / IPv6 频道全挂

需要三层都支持 IPv6：宽带、路由器（开启 IPv6 且下发前缀）、电视（拿到 v6 地址）。任一层没有，IPv6 源就不可用，`build-live6.py` 会跳过或生成空列表。此时忽略这个清单即可，IPv4 的 `/live.m3u` 不受影响。

## 路由器重启后电视连不上

电脑 IP 变了。去路由器后台给中转机做 DHCP 保留（按 MAC 绑定），以后地址就固定了。已经变过的话，电视上的配置地址要重新填一次。

## 日志里一直在 failover

说明主源持续不可用，`sources.json` 的 `active` 可能还指着它（中转能兜底，但每次请求都多绕一圈）。跑一次体检让它改指向：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\daily-check.ps1
```

如果三条源全挂，去上游仓库找新配置，改 `items[].url` 后重跑体检即可，电视端不用动。

## 中转会不会把配置暴露到公网

不会。程序只监听局域网端口，没有认证也没有公网出口。唯一要注意的是别在路由器上给 8080 做端口转发；`/tv.json` 会把站点列表和采集接口地址交给任何能访问它的人。
