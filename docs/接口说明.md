# 接口说明

中转是一个基于 `http.server` 的单进程服务，全部为 `GET`（也支持 `HEAD`），默认监听 `8080`。

- 基地址：`http://<中转机IP>:8080`
- 响应头统一带 `Access-Control-Allow-Origin: *`、`Cache-Control: no-cache`
- 除 `/`、`/status.json` 外均由程序动态生成，不需要认证（仅限内网使用）

## 一览

| 路径 | 返回 | 用途 |
| --- | --- | --- |
| `/` | HTML | 状态页 |
| `/health` | text | 存活探测，固定返回 `ok` |
| `/tv.json` `/tvbox.json` `/api.json` | JSON | 电视端配置（核心接口） |
| `/live.m3u` `/live.m3u8` `/live.txt` | M3U | 直播列表 |
| `/live-ln.m3u` `/live-full.m3u` `/live6.m3u` | M3U | 本机生成的附加清单（文件不存在时 404） |
| `/status.json` | JSON | 最近一次体检结果 |
| `/vod/stats` | JSON | 点播加速运行状态 |
| `/vod/cms/<token>` | 上游原文 | 采集站 API 代理 |
| `/vod/p?u=<b64url>` | M3U | 播放表代理，改写分片地址 |
| `/vod/s?u=<b64url>` | 分片字节 | 分片，命中缓存则读本地 |
| `/<其它路径>` | 上游原文 | 反代到当前视频源同一路径 |

## `/tv.json` — 电视端配置

按 `sources.json` 的 `video.active` 取上游 JSON，然后依次做五件事：

1. **失败降级**：当前源取不到或 JSON 解析失败，按 `items` 顺序试下一条，切换写进 `relay.log`；
2. **注入直播源**：`lives` 强制改成中转自己的地址（`/live.m3u`；若存在 `live-ln.m3u`、`live-full.m3u`、`live6.m3u` 一并列出）；
3. **站点排序**：读 `relay/vod-rank.json`，按体检分层重排 `sites`（1/3 层提到最前，2 层次之，4/5 层沉底）；
4. **采集接口改写**：站点 `api` 换成 `/vod/cms/<b64url(原api)>`，播放地址才能走点播加速；
5. **spider 版本号**：`spider` 里的 md5 前 8 位追加成 `?v=`，上游换 jar 后 TVBox 会重新下载，避免沿用坏掉的旧缓存。

配置内容按 mtime 缓存 120 秒；上游配置里以 `//` 开头的整行注释会被剔除（部分源带说明注释，标准 JSON 解析器不认）。

```bash
curl -s http://127.0.0.1:8080/tv.json | head -c 400
```

错误：所有源都失败 → `502`，正文提示查看 `relay.log`。

## `/live.m3u` — 直播列表

优先级：

1. `relay/live.m3u`（`tools/build-live.py` 生成，含 `#EXTINF` 才认）；
2. `sources.json` 的 `live.active`，失败降级到备源；
3. 全失败 → `502`。

```bash
curl -s http://127.0.0.1:8080/live.m3u | head -20
```

## 点播加速三件套

### `/vod/cms/<token>`

`token` 是上游采集站 API 的 URL-safe Base64（去掉 `=`）。中转解码后把查询串原样拼回，向采集站发起请求，并把响应里的播放地址改写成 `/vod/p?u=…`。

```bash
# 生成 token
python -c "import base64;print(base64.urlsafe_b64encode(b'http://example.com/api.php/provide/vod').decode().rstrip('='))"
# 调用
curl -s "http://127.0.0.1:8080/vod/cms/aHR0cDovL2V4YW1wbGUuY29t...?ac=detail&wd=测试"
```

### `/vod/p?u=<b64url>`

`u` 是 m3u8 的 Base64。中转取回播放表后：

- 分片、密钥、子播放表地址全部改写为 `/vod/s?u=…`；
- 触发后台预取，用 `TVBOX_VOD_CONNS` 条连接按顺序把整集拉到 `relay/vodcache/s/`；
- 开头 `TVBOX_VOD_FAST_START` 个分片用 Range 分段并发，专门抢起播。

### `/vod/s?u=<b64url>`

分片请求：

1. 命中本地缓存 → 直接读盘返回（内网速度）；
2. 未命中 → 最多等 `TVBOX_VOD_WAIT` 秒等预取；
3. 等超过 6 秒 → 这一片单独插队抢；仍失败则自己直连上游（最多重试 2 次）。

支持 `Range` 请求，正常返回 `200` 或 `206`。缓存超过 `TVBOX_VOD_CACHE_MB` 时按修改时间从旧到新删到 80%。

### `/vod/stats`

```json
{ "key": "…", "total": 620, "done": 310, "failed": 2, "at": 1762...,
  "stop": false, "bytes": 123456789, "served": 98765432, "episodes": 3,
  "cache_mb": 812.4, "conns": 28, "since": 42.1 }
```

`done/total` 是预取进度，`bytes` 是已下载字节，`served` 是已发给电视的字节，`since` 是本集预取已运行秒数。

## 反代

未匹配的路径（`/spider.jar`、`/lib/*.js`、`/*.json`、`/js/*` 等）会被代理到当前视频源配置的同名路径：

- 静态资源缓存 24 小时（`relay/cache/`），过期后先用旧值、后台刷新；
- `.jar` 会按配置里的 `md5;…` 校验，不一致重取一次，仍不一致就记录日志并返回原样内容交给 TVBox 判断；
- 按扩展名给出 `Content-Type`（jar / js / json / png / m3u8 等）。

## 错误码

| 码 | 场景 |
| --- | --- |
| `200` | 正常 |
| `206` | Range 分片 |
| `400` | `/vod/p`、`/vod/s` 的 `u` 缺失、解码失败或不是 http(s) |
| `404` | `/status.json` 还没有、`/live-ln.m3u` 等文件未生成 |
| `416` | Range 起点超出文件长度 |
| `502` | 上游取不到：全部视频/直播源失败、采集接口异常、播放表或分片拉取失败 |

所有 `502` 的正文都带简短原因，完整堆栈不在响应里，去 `relay.log` 看。

## 日志

`relay/relay.log`，每行 `时间  内容`，超过 2 MB 轮转为 `relay.log.1`。关注这几类：

| 关键字 | 含义 |
| --- | --- |
| `client <ip> GET <path>` | 外部设备（电视/手机）的请求 |
| `video failover -> …` / `live failover -> …` | 自动切换了源 |
| `vod prefetch start` | 开始预取一集 |
| `vod seg fail` | 某个分片反复失败 |
| `jar md5 mismatch` | spider.jar 与配置声明的 md5 不一致 |

## 端口与并发

- 端口：`TVBOX_RELAY_PORT`，默认 `8080`；改端口后电视地址要同步改。
- 并发：`TVBOX_VOD_CONNS` 默认 `28`。这个值是实测出来的——单连接 0.5~0.9 Mbps 时，24 条以上才能把 1~2 Mbps 的片源喂满。
- 监听地址：程序绑定 `0.0.0.0`，局域网内设备都能访问，电视换 IP 也不用改服务。**不要在路由器上做 8080 的公网端口转发**，这个服务没有认证，只该留在内网。
